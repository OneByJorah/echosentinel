# Operations guide

## Daily use

| Task | Where |
|---|---|
| Listen live | Live Audio → channel card → **Listen** (browsers require a click before audio plays) |
| See what was said | Live Transcription panel, or **Transcripts** (search, filter, export TXT/JSON/CSV) |
| Review detections | **AI Events** → acknowledge, dismiss false positive, bookmark, add a note, play the ±5 s clip |
| Go back in time | **Recordings** → pick channel/date → timeline (amber waveform, purple speech, red events, hatched offline) → click to seek |
| Export evidence | Recordings → clip export (≤ 15 min). The MP3 carries an `X-EchoSentinel-Meta` header with channel and UTC start/end; the export is audit-logged. |
| Summarise a period | Automation → Summaries → choose window → generated by your local Ollama, always labelled AI-generated with links to the cited segments/events |

## Service commands

```bash
systemctl status echosentinel          # state
journalctl -u echosentinel -f          # logs (credentials are redacted)
systemctl restart echosentinel
curl -s http://127.0.0.1:8640/healthz  # liveness
curl -s http://127.0.0.1:8640/readyz   # DB + storage checks
curl -s http://127.0.0.1:8640/metrics  # Prometheus (loopback only)
echosentinel retention                 # run retention immediately
echosentinel reset-password --username admin
```

## Channel states

| State | Meaning | What to do |
|---|---|---|
| ONLINE | Audio packets are flowing | — |
| CONNECTING | Probing / starting FFmpeg | wait a few seconds |
| OFFLINE | Unreachable, refused, timed out, stream ended or stalled | check power/network; **Reconnect** skips the backoff wait |
| ERROR | Authentication failed, unsupported codec, or no audio track | fix credentials / enable audio on the camera |
| DISABLED | Turned off by an admin | Channels → enable |
| UNCONFIGURED | No URL saved for the slot | Channels → add URL |

Reconnects back off exponentially from `ES_RECONNECT_BASE_S` to `ES_RECONNECT_MAX_S` with jitter, so four dead cameras never hammer the network. **Channels → Diagnostics** shows FFmpeg restarts, bytes received, the last error and the state history.

## AI components

The System page shows each one separately and honestly:

| Component | States | Notes |
|---|---|---|
| Speech-to-text (faster-whisper) | ready · loading · not_installed · error · disabled | `error` usually means weights aren't cached and the host is offline → run `scripts/fetch-models.sh` |
| Acoustic classifier (YAMNet) | ready · not_configured · not_installed · error · disabled | `not_configured` = model file missing; **no events are produced** in that state |
| VAD | silero / energy | Silero ships with faster-whisper |
| Ollama (text reasoning) | running · unreachable · disabled | Only used for summaries; set URL/model in Settings |
| Diarization | unavailable | Speaker labels are never shown until a validated model exists |

### Tuning detections

Settings → Thresholds. Defaults are deliberately conservative (e.g. gunshot-like 0.60, vehicle 0.60 with a 2-minute cooldown, speech-as-event off). Raise a threshold if you see repeat false positives; the cooldown suppresses duplicates per channel+category. Acoustic classification is probabilistic — treat it as a prompt to listen, not as proof.

### Performance

`/metrics` and System show STT/classifier queue depth, p50 latency and **dropped** counts. If drops climb: use a smaller Whisper model (`ES_STT_MODEL=tiny`), disable transcription on channels that don't need it, or add a GPU.

## Storage & retention

* Recordings: deleted after `retention_days`, and oldest-first when the total exceeds `max_storage_gb`.
* Disk guard: when free space falls below `min_free_gb`, recording pauses automatically (live monitoring continues), a notification is raised, and it resumes when space recovers.
* Transcripts/events: deleted after `transcript_retention_days`; **bookmarked events are kept**.
* Every retention run that deletes something writes an audit entry.

## Backup & restore

```bash
sudo ./scripts/backup.sh                      # DB (online, consistent) + env file
sudo ./scripts/backup.sh --with-recordings    # also audio
sudo systemctl stop echosentinel && sudo ./scripts/restore.sh <archive> --force && sudo systemctl start echosentinel
```

Backups contain `ES_SECRET_KEY` — store them encrypted. Suggested cron: `0 3 * * * /opt/echosentinel/scripts/backup.sh`.

## Troubleshooting

| Symptom | Check |
|---|---|
| Channel stuck OFFLINE "Connection timed out" | `ffprobe -rtsp_transport tcp rtsp://…` from the host; try transport UDP/TCP in Channels |
| ERROR "Authentication failed" | camera user/password; some cameras need a separate RTSP user |
| ERROR "Stream has no audio track" | enable audio in the camera's encoder settings |
| No transcripts | System → STT state; is speech loud enough? (energy gate adapts to background noise) |
| No events | System → classifier must be `ready`; thresholds may be too high |
| Listen button does nothing | browser autoplay policy — click again; check that the reverse proxy passes WebSockets |
| "ES_SECRET_KEY is not configured" | set it in the env file and restart |
| Recording paused | free disk below `min_free_gb`; lower retention or add storage |
